Capabilities

What BAITSSS Desktop can do as one integrated scientific system.

BAITSSS Desktop now supports two complementary desktop routes: the mature spatial workflow built around Landsat, gridded environmental data, and NLDAS forcing, and a newer Upper workflow that runs from local weather-station data through conditioning, reference ET, BAITSSS simulation, Results, and controlled Original versus Conditioned comparison.

Integrated system
Established capability

One project from field definition through scientific Results.

The maintained spatial BAITSSS Desktop workflow combines project setup, AOI definition, Landsat and environmental preparation, hourly forcing, execution of the BAITSSS model, long-run recovery, Results inspection, selected-pixel analysis, and export without separating the science from the project record.

Field, projects and data
Established capability

Define the study, preserve the run, and prepare aligned inputs.

Projects keep their identity, simulation period, data sources, validation state, and independent runs while the spatial and environmental inputs are prepared for the model grid.

Desktop projects and independent runs

  • Windows desktop scientific application
  • Create, open, switch, and manage persistent projects
  • Maintain multiple independent projects
  • Run multiple independent simulations within one project
  • Preserve project identity and simulation period
  • Freeze scientific configuration at run start
  • Keep previous runs and Results rather than overwriting them

AOI and model grid

  • Define, inspect, save, and reopen an Area of Interest
  • Review the AOI against map and raster context
  • Maintain geographic alignment across reopen and project switching
  • Validate CRS, extent, grid, and spatial compatibility
  • Use a 30 m Landsat-based model grid for spatial projects
  • Preserve point and single-cell spatial identity where supported

Landsat and vegetation

  • Landsat 7, 8, and 9
  • Scene discovery and period-based processing
  • AOI-aware and model-grid-aligned preparation
  • NDVI and LAI representation
  • Seasonal vegetation progression between observations
  • Source-scene and processed-product traceability
  • Landsat preview and spatial inspection

Environmental base data

  • NLCD land cover
  • Soil Field Capacity
  • Soil Available Water Capacity
  • BAITSSS Desktop base-data library for supported layers
  • Supported automatic static-layer selection
  • Review and replacement where supported
  • Validation before an unverified replacement becomes authoritative

Weather and reference ET

  • NLDAS hourly meteorological forcing
  • Complete-hour coverage checks for the requested period
  • Missing-data and readiness validation before Run
  • Continuous hourly forcing through the simulation

Installation and portability

  • User projects separated from replaceable application files
  • Updates and reinstalls preserve user projects and completed Results

Execution and long runs
Established capability

Long simulations are designed to stop safely, resume, recover, and protect storage.

Stop, pause, resume, and recovery

  • Committed-hour checkpoints
  • Safe Stop at a committed-hour boundary
  • Safe Pause at a committed-hour boundary
  • Resume existing from the next uncommitted hour
  • Committed hours remain preserved
  • Recoverable failed run when a valid checkpoint exists
  • Recovery from the last valid committed checkpoint after interruption

Long-run storage and disk protection

  • Runtime disk-space protection
  • Bounded storage for long simulations
  • Lossless storage of older hourly spatial outputs
  • Historical Results remain accessible
  • Storage optimization is not allowed to change scientific pixel values

Finalization

  • Run-specific final Results generation
  • Final hourly simulation CSV
  • Finalization tied to the selected run
  • Supported restart or recovery of finalization from valid partial state

Upper local station workflow
Active development · end-to-end route established

Local station data can now move through conditioning, BAITSSS execution, and comparative Results.

The Upper workflow is a newer route alongside the mature spatial workflow. It now connects a project-owned local weather station to conditioning, internal reference ET, explicit Original or Conditioned forcing, full Upper simulation, Results graphs, and controlled comparison tools.

Local station authority

  • Local hourly weather-station CSV input
  • Required latitude, longitude, and elevation
  • Strict hourly timestamp and full-period validation
  • Weather and NDVI completeness checks
  • Canonical hourly station data retained with the Upper project
  • Saved source authority with explicit CSV replacement

Conditioning and reference ET

  • Dedicated Conditioning Parameters
  • Conditioned weather generation for BAITSSS forcing
  • Internal short and tall reference ET preparation
  • Original Weather and Conditioned Weather preserved as explicit alternatives
  • Effective-input audit for the Upper workflow

Upper simulation

  • Explicit simulation-weather selector
  • Run Full Simulation from either Original or Conditioned Weather
  • Model Parameters retained as a separate project authority
  • Run-specific outputs and provenance
  • Upper Results opened directly from the completed workflow

Upper Results and comparison

  • Hourly and Daily Results views
  • ET, vegetation, soil water, water inputs, and weather time series
  • Weather Data and Reference ET comparison tabs
  • Scatter and Time Series comparison views
  • 1:1 scatter reference
  • Sample count, means, bias, RMSE, and R² statistics

Current validation boundary

  • Weather comparisons are operating in the current development build
  • Short and tall RefET comparisons are operating in the current development build
  • BAITSSS ET comparison controls are present
  • Matched opposite-weather BAITSSS run discovery remains under active validation and is not yet presented as complete

Development pace

The spatial workflow reflects years of scientific development, difficult iteration, and continued refinement, brought into its present desktop form through an especially concentrated period of modernization and validation in 2026. Most of the current Upper route advanced from station intake to this substantial end-to-end state through a short period of focused development built on that much longer foundation. The evidence requirement remains unchanged: a capability is promoted only after its run authority, provenance, scientific outputs, and Results path are verified.

Current status: the Upper route is no longer only a planned intake path. End-to-end execution and major Results functions are present in development. The remaining comparison and integration details are being verified before the route is promoted to the same established status as the mature spatial workflow.
