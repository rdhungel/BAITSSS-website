People & Scientific Stewardship

Clear responsibility for the science, software, and continuing development of BAITSSS.

BAITSSS has a research history that extends across earlier scientific work and institutions. The current desktop software also needs an unambiguous answer to a simpler question: who is responsible for maintaining it now? This page separates current stewardship from the broader scientific lineage so that credit and accountability remain clear.

01 · Current responsibility

Current development and scientific stewardship

Current development team
BAITSSS Development Team
Scientific model stewardship, desktop software development, verification, documentation, and release preparation
Current responsibility covers BAITSSS Desktop software development and maintenance, scientific continuity, verification, release preparation, documentation, and research collaboration pathways.

The BAITSSS Development Team brings together scientific and technical experience in evapotranspiration, irrigation and agricultural water management, remote sensing, soil-water processes, field instrumentation, and scientific model development. The team also includes continuity from the original development of the BAITSSS model, helping preserve its established scientific basis as the software continues to evolve.

For BAITSSS Desktop, the current responsibility is broader than writing code. It includes preserving the established scientific model behavior while reorganizing the research implementation into a maintained Windows desktop system, verifying numerical equivalence, controlling data and parameter authority, testing run and recovery behavior, packaging the scientific runtime, documenting the software, and preparing the first release version.

The software-development record and its current maturity are documented separately on Software Development & Verification, rather than being implied by an individual biography.

02 · Current responsibilities

What scientific stewardship means in the current BAITSSS project

01 · SCIENCE

Protect the model lineage

Scientific equations, state behavior, parameters and reference outputs are treated as controlled model assets. Software modernization is not allowed to silently redefine the science.

02 · SOFTWARE

Maintain one supported desktop route

The current goal is a coherent BAITSSS Desktop product with controlled project state, data preparation, execution, recovery, Results, provenance, packaging and documentation.

03 · VERIFICATION

Require evidence for changes

Long-run numerical comparisons, deterministic restart tests, source locks, runtime contracts, parameter-authority audits and release acceptance are used to separate demonstrated behavior from assumption.

04 · DOCUMENTATION

Make capabilities and limits visible

Scientific basis, software capability, access, development status and current maturity should be stated so researchers can judge BAITSSS without relying on private knowledge of the development history.

05 · COLLABORATION

Support research use responsibly

Research and educational use is connected to documented access and collaboration pathways so project expectations, software status and scientific responsibility remain explicit.

06 · CREDIT

Keep present responsibility separate from historical contribution

Current software stewardship does not erase the earlier scientific work, institutional settings, publications and contributors through which BAITSSS developed.

03 · Scientific lineage

Current stewardship is only one part of the BAITSSS history.

BAITSSS did not begin with the current desktop software. The scientific model developed through earlier research implementations, field studies, institutional collaborations, publications, and subsequent extensions. Those contributions remain part of the model’s scientific record and should be credited through the publications and historical documentation associated with the work.

Why the separation matters

A software visitor needs to know who currently maintains the product. A scientific reader needs to know where the model came from. Combining those into a generic “team” list would blur both responsibilities. BAITSSS therefore presents current stewardship and historical scientific lineage separately.

04 · Accountability

Responsibility should be visible, not inferred.

BAITSSS should be evaluated through its published science, documented software behavior, verification evidence, and clearly identified current stewardship. The website does not use a large-team presentation to imply organizational scale that the current software project has not earned.
