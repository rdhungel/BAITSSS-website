BAITSSS Desktop V1: Scientific Modeling Software for Field-Scale Evapotranspiration, Soil Water, and Irrigation Analysis

Ramesh Dhungel

September 11, 2026

Abstract

BAITSSS Desktop V1 is the first release version of a Windows desktop scientific modeling system developed for field-scale analysis of evapotranspiration, soil water, and irrigation. The software organizes project definition, environmental input preparation, readiness checks, continuous hourly simulation, mapped and pixel-scale result inspection, scientific export, checkpoint recovery, and run provenance within one persistent project environment. The scientific core couples a two-source surface energy balance with surface-layer and root-zone soil water accounting so that modeled states are carried continuously between satellite observation times. BAITSSS Desktop V1 is intended for research, education, and technical investigation where transparent inputs, assumptions, run identity, and comparison with independent evidence are important. A successful software run is not itself evidence of model accuracy; scientific evaluation remains dependent on appropriate field observations, comparison data, and the conditions of each application.

1. Scientific purpose

Satellite observations provide important spatial information but do not directly observe all field processes at every hour. BAITSSS advances the water and energy balance between observations using weather, vegetation information, soil properties, surface and root-zone state variables, and management assumptions. The model produces evapotranspiration, vegetation and soil evaporation-transpiration components, soil water conditions, and modeled irrigation requirement together with records needed to interpret each run.

2. Desktop V1 workflow

BAITSSS Desktop V1 packages the research model into a controlled desktop workflow. A project defines its spatial domain and simulation period, prepares and checks required data, executes the hourly scientific model, preserves restart checkpoints, and exposes results through maps, selected-pixel time series, exports, run records, and provenance. Project and run records are maintained separately from the replaceable application payload.

3. Scientific and computational behavior

The simulation advances sequentially in time because each hour begins from the state produced by the previous hour. Within an hour, spatial work can be distributed across persistent CPU workers, but the hour is completed before its resulting state is committed as the starting condition for the next hour. The desktop package also records frozen run configuration and supports checkpoint-based continuation after an interruption when a valid checkpoint remains.

4. Outputs and interpretation

Primary outputs include evapotranspiration, separate vegetation and soil contributions, surface-layer and root-zone water status, modeled irrigation requirement, maps, pixel time series, and scientific exports. Modeled irrigation requirement is distinct from known or recorded irrigation applied in a field. Results should be interpreted with the associated assumptions, inputs, spatial and temporal support, and independent evidence available for the application.

5. Scientific stewardship and limitations

Software verification and scientific validation answer different questions. Verification tests whether the implemented pathway behaves as intended and preserves established numerical behavior. Validation evaluates model performance against suitable independent observations. Neither substitutes for the other. BAITSSS Desktop V1 therefore retains run identity, configuration, input provenance, readiness records, and scientific outputs so that model behavior can be examined rather than treated as an unexplained software result.

6. Software status

BAITSSS Desktop V1 is the first release version of the desktop product line. The public software page documents the implemented workflow, current development and release status, computational observations, and access information. The scientific history of BAITSSS extends across earlier peer-reviewed research applications and collaborations; those historical institutional contributions do not imply current sponsorship, ownership, endorsement, or responsibility for the independent desktop software unless explicitly stated.
