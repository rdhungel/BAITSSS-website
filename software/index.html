Scientific workflow

Prepare. Verify. Simulate. Examine. Evaluate.

01

Prepare the project

Create or reopen a project, define the spatial domain and simulation period, and organize the required environmental inputs.

02

Verify readiness

Check temporal coverage, required variables, spatial compatibility, data preparation status, and other conditions that must be satisfied before execution.

03

Simulate hourly

Run the continuous hourly water and energy balance while preserving the state carried from one hour to the next.

04

Examine Results

Review mapped outputs, selected pixel time series, soil water conditions, modeled irrigation information, run identity, and scientific exports.

05

Evaluate the science

Use independent observations and other suitable evidence, when available, to investigate model behavior and scientific performance.

Desktop package

What you get with BAITSSS Desktop

BAITSSS Desktop V1 packages the Windows application, scientific runtime, project structure, readiness checks, execution, recovery, and Results tools around one persistent workflow.

Windows desktop application

Home, AOI, Data, Run, and Results are organized in one desktop interface.

Bundled scientific runtime

The scientific runtime ships with BAITSSS, so the workflow does not depend on a separate user-managed science Python environment.

Persistent projects and runs

Projects remain separate from the replaceable application payload. Each run keeps its identity, frozen configuration, checkpoints, validation records, output location, and Results products.

Checkpoint and recovery

Long simulations use committed-hour checkpoints so interrupted runs can continue from the next valid uncommitted hour when a usable checkpoint remains.

Scientific readiness checks

Inputs and readiness conditions are reviewed before execution so missing coverage, required information, or incompatible preparation can be identified before the model runs.

Results and pixel inspection

Run-specific maps, selected pixel time series, ET and soil water review, modeled irrigation information, CSV exports, PNG outputs, and supported reports are available from Results.

Long-run storage protection

Disk protection and lossless bounded storage support long spatial runs while keeping historical hourly raster data available.

Maintained documentation

Software guidance covers user controls, persistence, stopping, recovery, limitations, and lifecycle expectations.

User data are separate from the application payload.
Installing or replacing BAITSSS is not intended to replace the user's project and run records. Application files are replaceable; project data and completed Results remain user data.

How BAITSSS Runs the Model

BAITSSS advances time sequentially because each hour starts from the surface and root zone state produced by the previous hour. Within an hour, spatial work can be divided into blocks and distributed across persistent CPU workers. The blocks are collected before the hour is completed, and that state becomes the starting point for the next hour.

Temperature calculation
BAITSSS calculates soil and canopy temperature states as part of the energy balance solution. Satellite thermal assimilation is not part of the current route.

What BAITSSS Produces

Evapotranspiration

Mapped and time series ET, with separate vegetation and soil contributions.

Soil water status

Surface layer and root zone water conditions carried through the simulation period.

Modeled irrigation requirement

Modeled irrigation requirement is separate from known or recorded irrigation applied in the field.

Analysis records

Maps, pixel time series, run information, scientific exports, settings, assumptions, and input provenance.
