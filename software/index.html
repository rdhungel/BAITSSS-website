Desktop package

What you get with BAITSSS Desktop

BAITSSS is packaged as a Windows desktop scientific application. The production package contains the application and the runtime resources needed to operate the implemented workflow; it is not a loose collection of development scripts.

Windows desktop application

The installed BAITSSS application provides the Home, AOI, Data, Run, and Results workflow in one desktop interface.

Bundled scientific runtime

The scientific execution runtime is shipped with BAITSSS in its documented application location, so the installed workflow does not depend on a separate user-managed science Python environment.

Application resources

Runtime package data includes the resources used by the desktop application, including local map resources, generated visuals, icons, report resources, and required application data files.

Persistent projects and runs

Projects remain separate from the replaceable application payload. Each scientific run keeps its own run identity, frozen configuration, checkpoints, validation records, output location, and Results products.

Checkpoint, stop, resume, and recovery

Long simulations use committed-hour checkpoints. A stopped or interrupted run can continue from the next valid uncommitted hour when a usable checkpoint remains.

Long-run storage protection

BAITSSS includes disk protection and lossless bounded storage for long spatial runs so historical hourly raster data can remain accessible without unlimited live-file growth.

Results and export tools

The installed workflow supports run-specific maps, selected-pixel time series, ET and soil-water review, modeled irrigation information, CSV exports, PNG outputs, and supported report products.

Maintained documentation

The package ships with the BAITSSS V8 Software User Guide and Runtime Lifecycle Acceptance guide in its documentation folder, covering software behavior, user controls, persistence, stopping, recovery, limitations, and lifecycle expectations.

User data are separate from the application payload.
Installing or replacing BAITSSS is not intended to replace the user's project and run records. Application files are replaceable; project data and completed Results remain user data.

How BAITSSS Runs the Model

BAITSSS advances time sequentially because each hour starts from the surface and root-zone state produced by the previous hour. Within an hour, spatial work can be divided into blocks and distributed across persistent CPU workers. The blocks are collected before the hour is completed, and that state becomes the starting point for the next hour.

Temperature calculation
BAITSSS calculates soil and canopy temperature states as part of the energy-balance solution. Satellite thermal assimilation is not part of the current route.

What BAITSSS Produces

Evapotranspiration

Mapped and time-series ET, with separate vegetation and soil contributions.

Soil-water status

Surface-layer and root-zone water conditions carried through the simulation period.

Modeled irrigation requirement

Modeled irrigation requirement is separate from known or recorded irrigation applied in the field.

Analysis records

Maps, pixel time series, run information, scientific exports, settings, assumptions, and input provenance.
