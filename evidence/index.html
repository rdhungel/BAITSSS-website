Evidence

Evidence is separated by what it proves.

Peer-reviewed scientific evaluation, software verification, computational performance, and ongoing comparison are different forms of evidence. BAITSSS reports them separately so a software test is not presented as model accuracy, and a scientific comparison is not presented as a software-equivalence test.

Evidence rule

Each result should identify the question being tested, the comparison authority, the conditions of the test, and the software or scientific context in which the result was obtained.

This separation is central to interpreting BAITSSS results correctly.

02 · Peer-reviewed record

Published scientific evaluation

Published studies

Field and site evaluations

BAITSSS has a peer-reviewed publication record covering defined study sites, climates, crops, observations, input sources, and experimental conditions.

The publication itself is the authority for the numerical result, study design, comparison method, and stated limitation.

Interpretation boundary

No single universal accuracy number

A result from one site or period should not be generalized automatically to every field. Scientific performance must be interpreted in the conditions under which the evaluation was performed.

03 · Software verification

Tests of the desktop execution system

These tests address whether the software executes the intended scientific workflow reliably. They are not substitutes for field validation.

01

Numerical equivalence

Modernized execution methods are compared with the accepted scientific reference under controlled conditions and defined numerical criteria.

02

Checkpoint and restart

Stop, resume, restart, and run-lifecycle behavior are tested separately so continuity of scientific state is not assumed from interface behavior.

03

Run identity and provenance

Project inputs, run configuration, software state, outputs, and execution records are preserved so a result can be traced back to the run that produced it.

04 · Computational evidence

Performance is reported as a workload measurement

Benchmarking rule

Workload, hardware, and timing belong together

Runtime is meaningful only with the size of the simulated area, number of model hours, execution configuration, and computer used for the test.

Current performance observations →
Interpretation boundary

Speed is not scientific accuracy

A faster execution route is useful only if the scientific state and outputs remain consistent with the accepted reference under the defined verification criteria.

05 · Ongoing scientific comparison

Independent observations and model behavior

Independent observations

Comparison across scale and time

Thermal observations, ET products, field measurements, soil-water observations, and irrigation records can provide independent comparisons. Spatial scale, temporal scale, measurement uncertainty, and management conditions must be considered before interpreting differences.

Model behavior

Sensitivity, resistance, and transferability

Resistance connectivity, parameter sensitivity, stability, assumptions, and transferability remain subjects of scientific evaluation rather than being treated as fixed proof of performance everywhere.

Evidence standard: published science, software verification, computational benchmarking, and ongoing experiments remain separate categories. A result should be traceable to its test conditions and evidence source before it is used as a public claim.
