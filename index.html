Core Research Focus · 2026

Evapotranspiration and agricultural water research in 2026

Evapotranspiration (ET) is the water lost through soil evaporation and plant transpiration. It is central to agricultural water use, but ET alone is not enough. The larger system includes soil-water storage, irrigation, vegetation, weather, surface energy exchange, thermal conditions, and hydrologic response.

Beyond standalone ET

Study the connected water system

Effective agricultural water research requires ET to be examined together with soil-water storage, irrigation, vegetation, weather, surface energy exchange, thermal conditions, and hydrologic response.

Key scientific challenges

What remains unresolved

Important research priorities include irrigation measurement, root-zone soil water, thermal observations, ET partitioning, advection, hysteresis, resistance behavior, scale, uncertainty, transferability, and long-term independent validation.

From preprocessing to science

Reusable infrastructure changes the work

Modern research infrastructure can handle much more of the data assembly, preprocessing, execution, recovery, and Results workflow, shifting more of the difficult work back to field experiments, observations, theory, and comparison across models and sites.

Role of BAITSSS Desktop. BAITSSS provides a controlled, reproducible environment for data, parameters, execution, Results, and provenance. Its responsibility is to carry the science it implements faithfully, including assumptions, limitations, and uncertainty. Running correctly is not enough.
A community enterprise. BAITSSS can provide the operational framework, but advancing process understanding remains a shared responsibility across the ET, hydrology, irrigation, remote-sensing, agricultural, atmospheric, and water-resources communities.

BAITSSS Desktop V1

First public release

A modern desktop environment built around the established BAITSSS science.

BAITSSS Desktop V1 brings project setup, data preparation, model execution, Results, and scientific export into one connected Windows application.

The modernization balances scientific continuity with usability, versatility, computational efficiency, reproducibility, and a cleaner software architecture. Fields, simulation periods, inputs, settings, runs, maps, time series, and exports remain connected within the same project.

The result is a more usable and maintainable platform for field-scale analysis, research, education, model evaluation, and collaborative scientific work, while preserving the underlying BAITSSS scientific model.

See your field in BAITSSS Desktop

From field definition to model results.

BAITSSS Desktop guides a project from field definition and base-data review through simulation setup, Landsat and NLDAS preparation, model execution, and Results.

01

Open BAITSSS Desktop

Create or open a project. Your field analysis stays inside one BAITSSS Desktop project.

02

Look at your field in the AOI Viewer

Locate the field and define or import the Area of Interest (AOI). BAITSSS Desktop shows the saved AOI directly on the map.

03

View field information

BAITSSS Desktop displays the AOI over NLCD land cover, DEM/elevation, Soil Field Capacity, and Soil Available Water Capacity. These base layers are already part of the BAITSSS Desktop system.

04

Choose the simulation period

Set the exact start and end dates for the period you want the BAITSSS model to simulate.

05

Download Landsat and NLDAS from BAITSSS Desktop

Use File → Import → Landsat or File → Import → NLDAS. Each import window shows the registered archive and provides Download Missing for the data still needed by the project.

06

Run and inspect Results

Run the selected period, then inspect model outputs such as total evapotranspiration across the field. Return to the same project, change the period, update the data, and run again.

You do not start by building a GIS data stack

BAITSSS Desktop already works with the field's land cover, DEM/elevation, soil field capacity, and soil available water capacity. The field and these base layers can be inspected directly inside the project.

The changing inputs are handled inside the desktop workflow

Landsat and NLDAS are the time-dependent datasets shown in the BAITSSS Desktop import workflow. The software keeps registered data in its BaseData archive, shows what is already present, and provides Download Missing when additional files are needed for the selected work.

One field workflow, from inputs to Results.

Define the AOI, review field data, choose the dates, prepare the changing inputs, run the simulation, inspect ET and water-balance results, and return to the same project for another period when needed.
